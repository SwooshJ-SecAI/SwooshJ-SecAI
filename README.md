## How I Think

Every system here follows the same discipline: **deconstruct the problem to its underlying logic, design the architecture explicitly, then automate it.** I don't ship black boxes. Each agent, framework, and tool is documented across five questions:

1. **Design** — the architecture map: how the system is shaped, as a visual model
2. **Purpose** — what it is, in one line
3. **What it solves** — the manual pain it eliminates
4. **How to use it** — inputs, invocation, example interaction
5. **How to build it** — the design rationale, so it can be rebuilt or adapted

If you open any agent or framework in these repositories, you will find it answered along those five axes.

## What I Build

### Security Engineering
Real-time threat intelligence, compliance automation, and vulnerability analysis — systems that surface signal instead of noise.

- **Cyber Intelligence Command Center (CICC)** — aggregates CISA KEV, NVD, EPSS, and RSS feeds, enriches and scores disclosures against a technology watchlist, and produces prioritized, actionable briefings
- **Vendor-Specific Security SME Agents** — a fleet of seven deep specialists (Splunk, Arctic Wolf, SentinelOne, Palo Alto, Darktrace, SecurityScorecard, Microsoft Purview), each authoritative in one platform
- **Vulnerability Report Summarizer** — turns raw scan output into executive-ready reports with CVSS scoring and MITRE ATT&CK mapping

### AI Engineering
Reusable frameworks and agent architectures that make automation scalable instead of one-off.

- **Learning Agents Framework** — turns any subject or certification into a structured study package (notes, first-principles breakdowns, quizzes, notecards, assessments), and spawns subject-specific study agents
- **Agent Design Framework** — a two-tier methodology (fast task agents vs. rigorous spec-driven agents) for designing new agents deliberately
- **Universal Reasoning Framework** — the first-principles analytical engine that powers concept deconstruction across the other frameworks
- **Architecture Map Design System** — the dark-theme, stakeholder-readable diagram language used across every system map in this portfolio
